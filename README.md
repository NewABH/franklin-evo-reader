# Franklin EVO Reader — C#

Один консольный EXE для Windows 10/11 x64. Код полностью перенесён на C#: Python не используется. Устанавливать Python или .NET на целевой ПК не нужно. [Скачать готовый EXE](downloads/FranklinEvoReader.exe?raw=true). После самостоятельной сборки файл находится в `dist\FranklinEvoReader.exe`. Запускайте из открытой консоли. Только чтение по Veeder-Root TCP; настройки устройства не меняются.

## Без фильтров — все резервуары, все данные, включая плотность

```cmd
FranklinEvoReader.exe --host 192.0.2.10 --port 8001
```

Программа отправляет **один запрос `i21400` для всех резервуаров**. Для выбранного резервуара используется `i214NN`. Запросы `i201` полностью исключены. Полный ответ — один JSON-массив за цикл. Каждый элемент — резервуар с полями непосредственно из данных консоли: `tank`, `product_code`, `device_time`, `status`, объёмы, уровень (`product_level`), вода, температура, масса и плотность, если они переданы.

В выводе **нет** `commands`, `ok`, `checksum_verified`, `attempts`, `units`, времени опроса ПК, `reports` и контейнеров `measurements`/`extra_fields`. Статус выводится исходной hex-маской, например `"status": "0000"`, без добавочных расшифровок битов. Проверки суммы и обработка ошибок продолжают работать внутри программы.

Названия `mass`, `density` и другие ключи — подписи программы по документации протокола. Устройство не передаёт имена полей или JSON: оно передаёт значения в фиксированном порядке. Таким образом, это декодированный вывод полей устройства, а не побайтовая копия TCP-ответа. Уровни, температура, масса и объёмы округляются до 2 знаков. Плотность (density и tc_density) выводится без деления, масштабирования и округления — точное значение после декодирования float32. Время консоли форматируется как ISO без добавления часового пояса. Неизвестные дополнительные числовые поля сохраняются как `field_11` и т.п., без выдуманного физического смысла.

Числа в JSON всегда используют точку. C#-версия сохраняет заданное количество десятичных знаков в JSON, например `34765.25` для массы; это JSON-числа, не строки. При разборе JSON другой программой завершающие нули могут исчезнуть: `15.70` и `15.7` — одно число. `--decimal-separator comma` применяется только к текстовому выводу явно выбранных параметров.

Все поля берутся из одного ответа `i214`. Дополнительные отчёты не запрашиваются даже при отсутствии нужного поля. Для побайтового сохранения ответов используется `--capture-dir`.

Это все данные **отчёта i214 (масса/плотность)**, а не все настройки, архивы и тревоги прибора. Прибор отвечает на запросы; TCP доставляет ответ частями, которые программа собирает до ETX и проверяет по контрольной сумме. [Форматы отчётов 201 и 214 в документации Veeder-Root](https://core-es.com/wp-content/uploads/TLS-450-Serial-Interface-Manual.pdf).

## Фильтры

| Аргументы | Результат |
| --- | --- |
| Только адрес и порт | Полный JSON всех резервуаров, включая плотность |
| Добавлен `--tank 4` | Полный JSON резервуара №4 |
| Добавлен `--parameter temperature` без `--tank` | Температура каждого резервуара, строки с номером и именем параметра |
| `--tank 4 --parameter temperature` | Только одно число |
| `--tank 4 --parameter level density temperature volume` | Четыре значения через `;` в заданном порядке |

```cmd
FranklinEvoReader.exe --host 192.0.2.10 --port 8001 --tank 4
FranklinEvoReader.exe --host 192.0.2.10 --port 8001 --tank 4 --parameter temperature --decimal-separator comma
FranklinEvoReader.exe --host 192.0.2.10 --port 8001 --tank 4 --parameter level density temperature volume --decimal-separator comma
FranklinEvoReader.exe --host 192.0.2.10 --port 8001 --parameter density --decimal-separator comma
```

Примеры текстового вывода: `15,29` для одного значения; `920,24;739,8499755859375;15,29;18671,54` для четырёх; `tank=4;density=739,8499755859375` при выборе параметра без номера резервуара. Показания меняются. Явный `product_level` — синоним `level`.

## Все доступные параметры

| Имя для --parameter | Значение | Текстовое форматирование |
| --- | --- | --- |
| `level`, `product_level` | Уровень продукта | 2 знака |
| `density` | Текущая плотность | Без масштабирования и округления |
| `temperature` | Температура | 2 знака |
| `volume` | Объём продукта | 2 знака |
| `tc_volume` | Температурно-компенсированный объём | 2 знака; только расширенный i214, на вашем EVO отсутствует |
| `ullage` | Свободный объём по данным консоли | 2 знака; только расширенный i214, на вашем EVO отсутствует |
| `water_level` | Уровень воды | 2 знака |
| `water_volume` | Объём воды | 2 знака; только расширенный i214, на вашем EVO отсутствует |
| `mass` | Масса продукта | Округление до 2 знаков после запятой, без масштабирования |
| `tc_density` | Приведённая плотность | Без масштабирования и округления, если передана |
| `product_code` | Код продукта, не название | Один символ |
| `status` | Маска статуса инвентаризации | 4 hex-символа |
| `delivery_in_progress` | Бит 0: приём продукта | 1 или 0 |
| `leak_test_in_progress` | Бит 1: тест герметичности | 1 или 0 |
| `invalid_fuel_height` | Бит 2: недостоверный уровень | 1 или 0 |
| `unknown_status_bits` | Остальные биты статуса | 4 hex-символа |
| `tank` | Номер резервуара из ответа | Целое число |
| `device_time` | Время консоли | YYMMDDHHmm |

Округление половин выполняется от нуля. В текстовом режиме сохраняются завершающие нули. Исходные единицы определяются настройками консоли. Для плотности математические преобразования не выполняются; --decimal-separator comma меняет только символ разделителя в текстовом выводе. Длинная дробная часть, например 739.8499755859375, соответствует декодированному значению float32 устройства. Температурный пересчёт не выполняется. Статусы инвентаризации не заменяют полный отчёт тревог. Параметры отдельных флагов (`delivery_in_progress` и другие) доступны только при явном запросе: это расшифровка битов полученной маски `status`, они не добавляются в полный JSON.

На проверенном EVO отчёт `i214` содержит 6 измерений: объём, масса, плотность, уровень продукта, уровень воды и температура. Поля `tc_density`, `tc_volume`, `ullage`, `water_volume` в этом ответе отсутствуют: в полном JSON они пропускаются, при явном запросе возвращается ошибка. Эти имена сохранены для консолей с расширенным ответом `i214`; перехода к `i201` нет. Неизвестные дополнительные поля сохраняются в полном JSON без придуманной интерпретации.

## Опции и обмен

Обязательны только `--host` (синоним `--ip`) и `--port`. `--help` и `--list-parameters` работают без подключения.

| Опция | Поведение по умолчанию |
| --- | --- |
| `--tank` | Все резервуары; при указании допустимо 1–99 |
| `--parameter`, `--param` | Все поля отчёта i214 в JSON; можно перечислить нужные имена через пробел |
| `--decimal-separator` | `dot`; `comma` — для явно выбранных параметров |
| `--interval` | Один цикл; значение включает повторение с паузой в секундах |
| `--connect-timeout` | 3 секунды |
| `--read-timeout` | 5 секунд на весь ответ |
| `--retries` | 2 повторные попытки; допустимо 0–10 |
| `--retry-delay` | 1 секунда |
| `--capture-dir` | Необязательная папка исходных бинарных ответов |
| `--list-parameters` | Список всех имён без подключения |
| `--help`, `-h` | Справка |

При любом наборе параметров программа использует только один отчёт `i214` за цикл (не считая повторных попыток при ошибке). Один запрос `...00` охватывает все резервуары, отдельные запросы на каждый резервуар не нужны. При `--interval` TCP-соединение сохраняется между циклами; повторный запуск EXE не требуется.

Разрешён только `i214TT`, включая `TT=00` для всех резервуаров. Контрольная сумма, номера резервуаров, дубликаты, размеры полей и конечность чисел проверяются. Предел ответа — 1 МиБ. При разрыве или повреждении выполняется ограниченный повтор на новом соединении; отказ команды и отсутствие выбранного поля не повторяются.

При ошибке stdout пуст, сообщение идёт в stderr, частичный успешный вывод не печатается. Полный JSON пропускает отсутствующие поля; явный запрос отсутствующего параметра даёт ошибку. Коды выхода: 0 — успех, 1 — ошибка, 2 — неверные аргументы, 130 — Ctrl+C. В циклическом режиме ошибочный цикл пропускается, опрос продолжается.

## Сборка и проверка

```powershell
dotnet run --project tests\ReaderTests.csproj -p:PublishAot=false -- -
powershell -ExecutionPolicy Bypass -File .\build-exe.ps1
```

Исходники: `Program.cs` — CLI и вывод, `Protocol.cs` — разбор протокола и округление, `Client.cs` — TCP, таймауты и повторы. Используются стандартные библиотеки .NET, платных и сторонних библиотек приложения нет. JSON записывается через `Utf8JsonWriter`, без динамической рефлексии.

Для сборки требуются .NET SDK 10 и инструменты Microsoft C++/Windows SDK для Native AOT. Они нужны только на компьютере сборки. Установите Microsoft Build Tools с компонентами C++ и Windows SDK. При наличии локального каталога tools/native скрипт также умеет использовать его; инструменты Microsoft в репозиторий не включены. Скрипт запускает тесты, собирает EXE, копирует README и проверяет полученный EXE на локальном TCP-сервере. Пакеты сборки можно восстановить из `tools\nuget-feed`, если они уже загружены.

Дополнительный вариант сборки без C++-компилятора: `powershell -ExecutionPolicy Bypass -File .\build-exe.ps1 -SelfContained`. Результат в `dist-self-contained`: один EXE со встроенной средой .NET, без Python. Он больше Native AOT и при первом запуске распаковывает собственные нативные компоненты в пользовательский временный каталог. Установка .NET пользователю также не нужна.

Тесты покрывают резервуары, объединение по номеру, отсутствие служебных данных в JSON, необязательные поля, фильтры, округление массы и остальных величин, запрет записи, контрольную сумму, повреждённые ответы, дубликаты, таймауты, повторное использование соединения и переподключение. Реальные ответы устройства в репозиторий не включены; тесты используют синтетические данные. Тесты не подключаются к реальному уровнемеру.

Таймауты и интервалы задаются положительным числом секунд, не более 4294967. Синтаксис `--host=192.0.2.10` также поддерживается. Системная локаль не влияет на десятичный разделитель. Python для разработки и работы программы не используется.

Версия 2.2.0. Плотность выводится без масштабирования и округления. Используется только отчёт i214. Размер Windows x64 Native AOT EXE — 2 196 992 байта. Контрольная сумма SHA256 находится в downloads/SHA256SUMS.txt. Адрес 192.0.2.10 в примерах условный: замените его адресом вашего устройства.
