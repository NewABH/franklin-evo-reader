# Franklin EVO Reader

Консольная программа на C# для чтения Franklin Fueling Systems EVO TS-550 / TS-550evo по Veeder-Root TCP.

[Скачать EXE для Windows x64](https://github.com/NewABH/franklin-evo-reader/raw/refs/heads/main/downloads/FranklinEvoReader.exe)

Один файл работает на Windows 10/11 x64 без установки Python или .NET. Сборка Native AOT. Контрольная сумма файла: [SHA256](https://github.com/NewABH/franklin-evo-reader/blob/main/downloads/SHA256SUMS.txt).

## Запуск

Запускайте EXE из командной строки. Обязательны только адрес устройства и порт:

```cmd
FranklinEvoReader.exe --host 192.0.2.10 --port 8001
```

Адрес `192.0.2.10` в примерах условный — замените его адресом вашего уровнемера.

Без фильтров программа возвращает JSON-массив всех резервуаров. При указании `--tank` возвращаются данные выбранного резервуара. Используется только отчёт `i214`: команда `i21400` для всех резервуаров или `i214NN` для одного. Один запрос за цикл, кроме повторных попыток при ошибках. Настройки устройства не изменяются.

```cmd
FranklinEvoReader.exe --host 192.0.2.10 --port 8001 --tank 4
FranklinEvoReader.exe --host 192.0.2.10 --port 8001 --tank 4 --parameter density
FranklinEvoReader.exe --host 192.0.2.10 --port 8001 --tank 4 --parameter level density temperature volume mass --decimal-separator comma
FranklinEvoReader.exe --host 192.0.2.10 --port 8001 --parameter temperature
FranklinEvoReader.exe --list-parameters
```

## Формат вывода

- Без `--parameter`: один JSON-массив за цикл, элементы отсортированы по номеру резервуара.
- С `--tank` и одним параметром: только значение.
- С `--tank` и несколькими параметрами: значения через `;` в указанном порядке.
- С параметрами без `--tank`: строка на резервуар, например `tank=4;temperature=15.29`.

JSON содержит поля ответа устройства: номер резервуара, код продукта, время консоли, маску статуса и доступные измерения. Уровень продукта в JSON называется `product_level`. Названия полей присваиваются по протоколу: устройство передаёт значения в фиксированном порядке, а не JSON. Служебные сведения о программе, попытках подключения и проверке суммы в JSON не добавляются.

Уровни, температура, объёмы и масса округляются до двух десятичных знаков; половины округляются от нуля. **Плотность `density` и `tc_density` выводится без масштабирования и округления.** Например, декодированное значение float32 может выглядеть как `739.8499755859375`.

JSON всегда использует точку. `--decimal-separator comma` меняет только разделитель в текстовом выводе выбранных параметров. Единицы измерений определяются настройками консоли. Время устройства в JSON имеет формат `YYYY-MM-DDTHH:mm:ss`, без присвоения часового пояса.

## Читаемые параметры

| Имя для `--parameter` | Значение | Формат |
|---|---|---|
| `level`, `product_level` | Уровень продукта | 2 знака |
| `density` | Плотность продукта | Без математических преобразований |
| `temperature` | Температура | 2 знака |
| `volume` | Объём продукта | 2 знака |
| `mass` | Масса продукта | 2 знака |
| `water_level` | Уровень воды | 2 знака |
| `product_code` | Код продукта | Символ из ответа |
| `status` | Маска статуса | 4 hex-символа |
| `tank` | Номер резервуара | Целое число |
| `device_time` | Время консоли | `YYMMDDHHmm` при отдельном запросе |
| `delivery_in_progress` | Бит 0 маски: приём продукта | 0 или 1 |
| `leak_test_in_progress` | Бит 1: тест герметичности | 0 или 1 |
| `invalid_fuel_height` | Бит 2: недостоверный уровень | 0 или 1 |
| `unknown_status_bits` | Остальные биты маски | 4 hex-символа |
| `tc_density` | Приведённая плотность, если есть в расширенном i214 | Без математических преобразований |
| `tc_volume` | Приведённый объём, если есть в расширенном i214 | 2 знака |
| `ullage` | Свободный объём, если есть в расширенном i214 | 2 знака |
| `water_volume` | Объём воды, если есть в расширенном i214 | 2 знака |

Набор измерений зависит от консоли и прошивки. Базовый ответ EVO содержит объём, массу, плотность, уровень продукта, уровень воды и температуру. Отсутствующие дополнительные поля пропускаются в полном JSON; явный запрос отсутствующего поля завершится ошибкой. Другие отчёты для получения этих полей не запрашиваются.

Расшифрованные биты статуса выводятся только при явном выборе. В полном JSON остаётся маска `status`. Неизвестные дополнительные измерения сохраняются в JSON как `field_11` и далее без присвоения физического смысла.

## Параметры подключения

| Опция | Назначение / значение по умолчанию |
|---|---|
| `--host`, `--ip` | Обязательный адрес устройства |
| `--port` | Обязательный TCP-порт, обычно 8001 |
| `--tank` | Номер 1–99; без опции — все резервуары |
| `--parameter`, `--param` | Имена через пробел; без опции — все поля в JSON |
| `--decimal-separator` | `dot` или `comma`; по умолчанию `dot` |
| `--connect-timeout` | Таймаут подключения, 3 секунды |
| `--read-timeout` | Таймаут всего ответа, 5 секунд |
| `--retries` | Повторные попытки после ошибки, 2; допустимо 0–10 |
| `--retry-delay` | Пауза перед повтором, 1 секунда |
| `--interval` | Пауза между циклами; без опции — один цикл |
| `--capture-dir` | Папка сохранения исходных ответов `.bin` |
| `--list-parameters` | Список параметров без подключения |
| `--help`, `-h` | Справка |

Таймауты и интервалы — положительные числа секунд не более 4294967. При циклическом опросе соединение сохраняется между запросами. Для остановки нажмите Ctrl+C.

## Обработка ошибок

Программа собирает ответ до ETX, проверяет контрольную сумму, соответствие команды, номера резервуаров, размеры полей и конечность чисел. Предел ответа — 1 МиБ. При обрыве, таймауте или повреждённом ответе повтор выполняется на новом соединении. Отказ команды и отсутствие выбранного поля не повторяются.

Ошибки выводятся в stderr, частичный результат не печатается. В циклическом режиме ошибочный цикл пропускается и опрос продолжается.

Коды завершения: `0` — успех; `1` — ошибка обмена, данных или файлов; `2` — неверные аргументы; `130` — Ctrl+C.

## Сборка и тесты

Для сборки нужны .NET SDK 10 и Microsoft Build Tools с компонентами C++ и Windows SDK. Эти инструменты нужны только разработчику. Платные библиотеки не используются.

```powershell
dotnet run --project tests\ReaderTests.csproj -c Release -p:PublishAot=false -- -
powershell -ExecutionPolicy Bypass -File .\build-exe.ps1
```

Скрипт проверяет код, собирает `dist\FranklinEvoReader.exe`, копирует README и проверяет готовый EXE на локальном тестовом TCP-сервере. При наличии локальных инструментов в `tools/native` и кэша пакетов в `tools/nuget-feed` скрипт использует их. Эти каталоги не включаются в репозиторий.

Дополнительная сборка со встроенной средой .NET: `build-exe.ps1 -SelfContained`. Файл получается в `dist-self-contained`; установка .NET на целевом ПК не требуется, но EXE больше и распаковывает нативные компоненты во временный каталог.

Исходники: `Program.cs` — CLI и цикл опроса; `Protocol.cs` — разбор i214 и форматирование; `Client.cs` — TCP, таймауты и переподключение. Тесты используют синтетические данные и не обращаются к реальному устройству. Для необязательной проверки собственных сохранённых ответов вместо `-` можно передать путь к папке `.bin`.
